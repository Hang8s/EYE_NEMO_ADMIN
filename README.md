# EYE NEMO Admin

Окрема українська адмінка архіву Telegram Business. React + TypeScript + Vite.
Основний репозиторій: `Hang8s/EYE_NEMO_ADMIN`; сайт: `https://hang8s.github.io/EYE_NEMO_ADMIN/`.

## Можливості

Огляд статистики; окремі власники та співрозмовники; чати, пошук у всіх версіях повідомлень;
медіатека у вигляді галереї або таблиці; комбіновані серверні фільтри; перегляд і завантаження медіа;
блокування архівування; незалежне фонове стирання; масові дії до 100 вибраних об’єктів;
стан операцій, повторення після помилки, журнал; зміна пароля та завершення сесій.

Перегляд чатів співрозмовника показує розмову повністю; медіа/повідомлення співрозмовника
фільтруються за відправником. Стирання працює лише з архівом на сервері та не видаляє повідомлень у Telegram.
Стирання без блокування зберігає нові повідомлення. Перелік об’єктів фіксується при створенні операції.
Стерті повідомлення не відновлюються повторними Telegram-подіями. Метадані окремо стертих файлів
залишаються в історії з позначкою недоступності. Вже завантажені на пристрій копії та
раніше надіслані адміністратору файли не відкликаються серверним стиранням.

## Локальна робота

```sh
npm ci
cp .env.example .env.local
npm run dev -- --host 127.0.0.1
```

Встановіть `VITE_API_BASE_URL` на адресу чинного бекенду. Для локального бекенду:
`http://127.0.0.1:8000`, а на бекенді `ADMIN_ORIGIN=http://127.0.0.1:5173`.
Адреса API — публічна конфігурація, не секрет. Службові ключі й пароль не додаються до Vite-змінних.

## Підготовка бекенду

Спочатку випустіть зміни в `EYE_NEMO_BACKEND` через його наявний release-процес.
Міграція `0008_admin` створює адміністративні таблиці. Потім у серверному середовищі:

```sh
uv run --frozen python -m scripts.create_admin
```

Команда інтерактивно запитує логін і пароль (від 12 символів) та створює єдиного адміністратора.

Для Vercel замість інтерактивного термінала можна додати секрет
`ADMIN_BOOTSTRAP_PASSWORD` у GitHub environment `production` бекенду. Release
створить першого адміністратора після міграцій; логін — `admin` (або значення
змінної `ADMIN_BOOTSTRAP_USERNAME`). Наявний пароль не змінюється. Після успішного
створення облікового запису видаліть одноразовий bootstrap-секрет.
Пароль хешується Argon2id; сервер зберігає тільки хеші випадкових сесійних токенів.
Сесія триває 8 годин; зміна пароля відкликає всі сесії. Ліміт входу — 10 спроб за 15 хвилин
через спільну базу, незалежно від інстансу сервера. `ADMIN_ORIGIN` у production:
`https://hang8s.github.io`. Службовий `ARCHIVE_API_KEY` не є адміністративною сесією.

Стирання використовує PostgreSQL outbox і наявний `archive-media` consumer Vercel Queues;
чинний recovery Cron повторно публікує пропущені операції. На постійному хостингу їх
обробляє наявний DB worker. Не використовуйте FastAPI BackgroundTasks як заміну durable worker.

## GitHub Pages

1. Створіть публічний `Hang8s/EYE_NEMO_ADMIN`, завантажте цей репозиторій у `main`.
2. У Settings → Pages оберіть GitHub Actions.
3. У Settings → Secrets and variables → Actions → Variables додайте
   `VITE_API_BASE_URL` з перевіреною production-адресою бекенду.
4. Workflow перевіряє контракти, TypeScript, тести і збірку, після чого публікує `dist`.

Публікується інтерфейс входу та код. Приватні дані отримуються тільки через `/admin-api`
із серверною перевіркою сесії. Маршрути hash працюють після оновлення сторінки без Pages rewrites.
Спочатку випускається бекенд, потім інтерфейс. При відкаті інтерфейсу міграції не скасовуються.

Workflow публікує Pages лише після перевірки, що production `/admin-api/auth/me`
відповідає очікуваним `401` без сесії. Якщо бекенд ще не випущений, перевірки й
збірка виконуються, а публікація пропускається; після випуску бекенду запустіть
workflow повторно через Actions → Run workflow.

## Перевірки та контракти

```sh
npm test
npm run contracts:test
npm run build
```

Повний браузерний сценарій із реальним API потребує сусіднього `../backend`:

```sh
npx playwright install chromium
npm run test:e2e
```

GitHub Actions окремо завантажує backend `main` для цього сценарію; бекенд із
адміністративним API має бути опублікований перед адмінкою. Перевірка створює
тимчасову базу й не використовує production-дані.

`contracts/openapi.json` і `src/generated/api.ts` збережені в репозиторії:
для незалежної CI-збірки backend checkout не потрібний. Поряд із `../backend`:
`npm run contracts:sync` оновлює snapshot із реального FastAPI та генерує типи.
Тестові fixture й runtime preview не підключаються до production-бази.

Експорт JSON/CSV/ZIP і багатокористувацькі адміністративні ролі не входять до цієї версії.
